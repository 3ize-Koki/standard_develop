# ウォーターフォール実務マニュアル

実作業において「どのタイミングで品質会議を行い、どの数値をどうやって集めるか」のガイドです。
具体的な合格基準（%や件数）は `quality_standards_master.md` を参照してください。

## 品質会議の実施タイミングと準備

### ① 見積もり提出前
* **タイミング**: 顧客へ見積もりや提案書を正式に提出する前
* **準備するデータ**: WBS、提案書、見積もり計算Excel。PERT法の期待値が使われているか、バッファが確保されているかを確認します。

### ② 要件定義後
* **タイミング**: 要件定義フェーズが完了し、設計・実装フェーズへ移行する前
* **準備するデータ**: 要件定義書、顧客との合意証跡（承認メールやBacklogの完了コメント等）。

### ③ テスト後
* **タイミング**: 総合テスト（システムテスト）が完了し、本番リリース準備に入る前
* **準備するデータ**: SonarQubeやGitHubの解析結果（カバレッジ等）、BTS（バグトラッキングツール）の消化状況。これらからバグ密度とテスト密度を算出します。

### ④ リリース前
* **タイミング**: 本番環境へのデプロイ（リリース作業）を行う直前
* **準備するデータ**: 脆弱性スキャン（Trivy, OWASP ZAP等）の結果レポート、リリースリハーサル結果の報告書。
